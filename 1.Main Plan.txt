Act as a Principal Software Architect, Senior Full-Stack Engineer, Database Architect, Excel Automation Specialist, Cybersecurity Engineer, UI/UX Designer, DevOps Engineer, and QA Automation Lead.

Your task is to audit, improve, complete, and production-harden my existing College Examination Result Automation Platform using the actual frontend, backend, database, business logic, and configuration available in the repository.

# PHASE 5 — AUTHORIZED RESULT AUTOMATION

Implement a reliable workflow for retrieving examination results through an officially permitted portal integration or authorized export mechanism.

Where automated browser interaction is permitted, use an appropriate tool such as Playwright.

## Processing workflow

1. Load eligible student records.
2. Validate Register Numbers and required input fields.
3. Establish the correct examination session.
4. Retrieve results through the approved mechanism.
5. Download the corresponding PDF where permitted.
6. Verify file integrity and student identity.
7. Extract subject codes, grades, and other supported result data.
8. Validate the extracted information.
9. Persist verified results transactionally.
10. Record processing status and sanitized errors.
11. Generate updated reports after successful validation.

Use Register Numbers as identifiers. If DOB is required by the official portal, handle it securely and avoid storing it unnecessarily.

Do not bypass CAPTCHA, MFA, rate limits, access controls, or other portal protections.

If additional human verification is required, pause the affected workflow and request staff intervention.

## Reliability

- Retry only transient errors.
- Apply sensible timeouts and backoff.
- Prevent concurrent duplicate processing.
- Support recovery after a worker restart.
- Preserve the last valid snapshot or result.
- Distinguish pending, failed, unavailable, and verified states.
- Continue processing independent records when one student fails.
- Record meaningful error details without exposing sensitive information.

# PHASE 6 — PDF EXTRACTION AND VERIFICATION

Use a suitable existing PDF library or a compatible library such as PyMuPDF or pdfplumber.

Support the actual PDF structure encountered in the authorized source.

Validate:

- Register Number.
- Examination session and semester.
- Subject code.
- Subject name when available.
- Grade or result status.
- Required record completeness.
- Duplicate and conflicting subject entries.

Do not assume all PDFs use identical layouts.

If the PDF is scanned or unreadable, flag it for manual review unless an approved OCR workflow exists.

Never silently convert extraction uncertainty into a pass, fail, or arrear decision.

Store the source PDF reference and verification metadata where appropriate.

# PHASE 7 — ADVANCED ENTERPRISE EXCEL ENGINE

Implement a reusable workbook-generation service using openpyxl or the project's existing compatible library.

## Required worksheets

1. Result Analysis.
2. Summary.
3. Arrear Analysis.
4. Processing Log.
5. Subject Mapping.

Generate only the sheets relevant to available data and established requirements.

## Dynamic result matrix

- One student per row.
- Unique subject codes become columns dynamically.
- Subject ordering remains deterministic.
- Results map to the correct student and subject.
- Register Numbers remain text identifiers.
- Student rows follow the institution's required ascending order.
- New semesters and subjects do not require hardcoded code changes.

## Professional formatting

Apply consistent formatting across all applicable worksheets:

- Professional institutional title and report metadata.
- Dark navy headers with readable white text.
- Appropriate fonts, font sizes, bold styling, and fills.
- Complete, consistent table borders.
- Sensible alternating row colors.
- Correct horizontal and vertical alignment.
- Dynamic column widths and row heights.
- Wrapped headers for long subject descriptions.
- Appropriate number and date formats.
- Freeze panes.
- AutoFilter or Excel Tables.
- Conditional formatting for validated academic and processing statuses.
- Clear totals and summary sections.
- Print areas, margins, page orientation, and repeated header rows.

Avoid merged cells inside the main data table.

## Formulas and calculations

Use formulas only where appropriate and based on verified rules.

Support relevant totals, percentages, grade distributions, and arrear counts.

- Avoid fixed ranges that exclude new students.
- Prevent division-by-zero errors.
- Do not treat missing results as arrears.
- Keep processing status separate from academic status.
- Protect against formula injection from untrusted source text.
- Set recalculation properties where supported.
- Independently verify important calculations in the backend.

If formula values have not been calculated by a spreadsheet engine, disclose that limitation instead of claiming the cached results are current.

## Workbook verification

After generation, reopen and validate the workbook.

Check:

- Worksheet names and order.
- Student and subject counts.
- Formula references.
- Table ranges.
- Borders, alignment, fills, and number formats.
- Freeze panes and filters.
- Conditional formatting.
- Print configuration.
- File readability and structural integrity.

Publish the workbook only after validation succeeds.
